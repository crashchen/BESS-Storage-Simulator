# 第九批：AUTO 晚高峰留电

日期：2026-09-23，CC 复审收尾于 2026-09-24（Europe/Berlin）。基线为已发布 main `b82425813910f2151495e3c2c74426ce61e89f1e`；本批在 `codex/audit-batch-9-peak-priority` 工作树。用户安排的 CC 第一轮复审确认实现与原三日数字，指出“晚峰价只要略高就留电”会亏；本收尾针对该发现，尚未经 CC 二次复审或发布。本代理未调用 CC。

## 决策与边界

用户提出晚高峰优先。旧 AUTO 夜间从电网/PV充到 40% SoC，06:00 后却允许白天本地负荷把电池放到 0%，导致多日晚高峰入场无电。新规则沿用既有 40% 数值：夜间充向该目标；**仅当晚峰相对肩段的价差足以覆盖效率、峰段配速余量和底部 12% 不再参加白天循环的价值时**，肩段有缺口也只使用超过 40% 的能量，PV 盈余仍可充电；18:00 后按原配速规则在 12% 峰段保留下放电。未过门槛则维持原肩段自用行为。手动模式、结算公式、PCC/PV 优先级及峰段放电价格门契约不改。

门槛只用配置常量和三个时段电价。令 `T=0.40`（夜间充电目标）、`R=0.12`（峰段保留）、`D=5h`（18:00–23:00 峰段）、`H=0.25h`（末尾配速地板），`f=1-(H/D)·exp(-1)` 是现有配速律在峰段结束前对可用能量的理想释放比例。仅当 `p_peak > p_mid` 且 `(T-R)·f·η_d·p_peak + [T-(T-R)·f]·p_off/η_c > T·η_d·p_mid` 时留电。左侧是晚峰释放价值与相对旧循环少购电的价值，右侧是旧策略把 40% 在肩段放完的价值。假设旧策略有足够肩段负荷放到 0%、夜间能补至 40%，且无 PV/PCC/功率限幅。默认 80/150 €/MWh 夜间/肩段电价与 0.96/0.96 效率下，门槛约为晚峰 **178.78 €/MWh**。

CC 建议的简式只算 12% reserve，未计峰段末尾按指数配速留下的少量电量，会在 177.5–178.5 €/MWh 启用留电；独立三日扫描表明该区间反而低 €750–€162。加入 `f` 后该区间维持旧策略，178.8 €/MWh 开始启用。这仍只是可解释的稳态启发式，不是负荷/PV预测或收益优化器；峰段放电本身仍无完整 round-trip 价格门。负价、容量/PCC 限幅和其他需求曲线可能改变真实结果，不能据此宣称普遍盈利。供电恢复价值是按结算电价计算的假设估值，不是现金收入。

## 同初末状态的三日对照

固定初态 06:00 / 40% SoC，默认 188 MW / 744 MWh、PV 117/102 MW、PCC 288 MW，运行 72 模拟小时至下一次 06:00；实时时步 0.1 秒、1440×，即各调用 `simulateTick` 1800 次。两策略的终态均为 40% SoC，避免把未放完的存量当作收益。本地对照把基线提交 `b824258` 的 `config.ts` 与 `tickEngine.ts` 通过 `git show` 注入旧引擎，其他模型源码与工作树相同；CC 另用 `git archive b824258 src` 取得完整旧源码并独立复现。复现时分别构建旧/新 `tickEngine.ts`，从 `createInitialGridState` 覆盖 06:00、40% SoC、1440×、负荷和三段电价，逐 tick 累计 `cumulativeRevenueEur`，同时读取 `cumulativeBessRestoredLoadAssumedValueEur` 与每日 18:00 SoC。在仓库根目录、`npm ci` 后运行 `node docs/audits/2026-09-23/compare-auto-policy.mjs` 可复核临界价扫描。

## 实现与验收入口

- `src/config.ts`：将原夜间 40% 目标明确命名为晚峰入场目标，避免两个可漂移的 40% 常量。
- `src/utils/autoPolicy.ts`与`tickEngine.ts`：共享含效率/峰段配速的闭式价差门槛，肩段选择 40% 或 0% 下限，并把 40% 加入 SoC 事件拆步；18:00 边界仍切换到既有峰段配速。
- `src/utils/bessDisplay.ts` 和 `BessControl`：说明条件留电；SoC 在目标以下的零功率读数不误报为正在放电或满电。
- `autoPolicy.test.ts`和`tickEngine.test.ts`：155–200 €/MWh 临界价、负电价、目标处停放、跨目标 tick 只结算前段、18:00 恢复峰段放电，以及反向价格不留电。
- `tickConvergence.test.ts`：100%/150% 负荷下三日每晚入场仍有目标电量，并比较粗细步长的 SoC 与全部金额字段。
