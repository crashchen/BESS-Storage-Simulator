## 解决的问题

- 原设备名称由Three世界坐标`Text`绘制，Full site在320/390px宽度取完整站区时随相机距离一起缩小，几乎不能阅读。现在五处名称用Drei `Html`贴在原3D锚点上，以固定CSS字号显示。CC发现初版误用`pointerEvents` prop，非transform模式下并未禁止标签拦截；收尾改为`style={{ pointerEvents: 'none' }}`，让点击落回Canvas。HUD设`z-10`高于标签。≤420px时隐藏较次要的LOCAL LOAD标签；图例仍解释本地负荷。≤480px时上移PCS标签，Grid标签横移，避免常见421–455px宽度的BESS/PCS交叠。Grid过载时标签恢复红色告警样式。任意手动相机角度下未做自动碰撞/遮挡管理。
- 原七路能流可见黄色、两种琥珀色、蓝色动画，却没有颜色和方向的说明。新增常显图例，解释太阳能、BESS向负荷/电网、Grid向BESS/负荷以及红色弃光粒子；移动点代表方向，每条线随本路功率变亮。颜色与场景共用`FLOW_COLORS`，图例随场景工具一起在抽屉打开时隐藏，不挡抽屉。
- 原BESS有简化方块占位，PCS和主变的Suspense fallback为空；图表lazy加载只有灰色脉冲块。现在三台GLB各有同尺度轮廓占位，Three加载管理器显示“Loading 3D equipment…”，图表显示带文字和简化图形的骨架。既有失败隔离、GLB清缓存重试与图表fresh-URL重试保持不变。

未修改`GridState`、reducer、AUTO规则、七路流量计算、功率结算或累计价值。图例阐述现有展示，不声称做了功率来源的新核算。

## 验收

Node 24.21.0：收尾后`npm run lint`、**223测试/21文件**、`BASE_URL=/BESS-Storage-Simulator/ npm run build`与`git diff --check`通过。原Three vendor chunk体积提示仍在，724.92kB / gzip187.62kB。本轮新增测试检查图例在抽屉下隐藏/恢复、3D等待状态不替换模拟控制，以及图表悬挂import时的可见文字和占位；原有模拟与相机测试全绿。由于App测试mock了drei，标签指针事件以浏览器为准。

本地真实浏览器在1280×720、390×844、320×640及844×390 CSS视口检查场景。320宽时四个主要标签的矩形无正面积交叠，图例底部约288px、最近标签顶部约292px；390宽时同样分开。1280桌面和844横屏的图例位于左侧空白，不覆盖默认站区。320/390下LOCAL LOAD世界标签隐藏，图例仍有负荷说明。相机自由旋转后未逐姿态证明标签不碰撞。

又检查了320×568与390×568短屏：图例在顶部中央，底部224px，最近设备标签从252px起；HUD、侧边抽屉入口与底部场景工具可见，控制台无error。此项是默认相机姿态下的布局检查。

CC复审后本地真实浏览器再次点检：PCS标签的CSS `pointer-events`及父元素均为`none`，标签中心的`elementFromPoint`命中Canvas；直接点击标签中心成功钉选PCS信息卡。默认全景在320×640、320×932、390×844、421×932、428×932、430×932、440×932、455×932、460×932及480×932未见标签矩形相交。HUD计算`z-index: 10`，高于标签的1。另在手动待机、150%负荷、1440×的真实浏览器运行至次日晚峰18:07，PCC显示5 MW overload，Grid标签计算样式为红色`text-rose-300`/`border-rose-400`，画面上也可见红色标签；console error为空。上述浏览器检查不等于任意旋转视角下的自动避让。

另用临时本地Pages子路径服务器将GLB和图表分包分别延迟8秒：先看到三台简化轮廓及3D加载文字；运行模拟积累历史后打开Metrics，看到图表加载文字与骨架。资源完成后两种加载状态消失，三GLB和图表正常出现，控制台error为空。该检查是**慢响应注入**，不是断网、503恢复或真实GPU故障注入；临时服务器未加入仓库。
